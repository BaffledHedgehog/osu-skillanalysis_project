СЛАЙД 01. pulse!
Говорит: Ляхов Я.П.

[На экране: "Пойми, что будет сложно именно тебе."]

Добрый день. Представляем pulse! - приложение для персонального анализа карт osu!standard.

osu! - ритм-игра, где нужно наводиться на объекты и нажимать клавиши в нужный момент. Карты требуют разных навыков: точного наведения, быстрых нажатий или чтения сложного ритма.

Наше приложение сравнивает карту с историей игрока и помогает заранее понять, что именно будет для него сложным. Сегодня показываем итоговую учебную версию проекта.


СЛАЙД 02. Одинаковые звезды. Разные трудности.
Говорит: Ляхов Я.П.

[На экране: "Как игрок выбирает сейчас" и "Что дает pulse!".]

В osu! есть общая сложность карты в звездах. Но два игрока могут по-разному справляться с одной картой.

Один уверенно играет прыжки между объектами, но теряется в быстрых сериях. Другой хорошо нажимает, но хуже справляется с наведением. Общее число звезд этих различий не показывает.

Наши первые пользователи - игроки с рейтингом 5-7 digit и те, кто уперся в один навык. Приложение показывает нагрузку относительно их истории и помогает выбирать карты осмысленнее.


СЛАЙД 03. Профиль + карта = персональный отчет
Говорит: Ляхов Я.П.

[На экране: профиль, история, карта, отчет.]

Сценарий состоит из четырех шагов. Игрок указывает профиль, собирает доступную историю, добавляет карту и получает отчет. После запуска не нужно специально наигрывать новые результаты.

В первой версии есть личные шкалы aim и speed, сложность выбранной карты, шанс прохождения и ожидаемая accuracy. Aim - наведение, speed - нагрузка на нажатия.

Полный профиль шестнадцати групп и план тренировок - дальнейшее развитие. Заказчик проекта - я, автор идеи. Теперь Гайфуллин покажет основной сценарий.

СЛАЙД 05. Историю собираем одной кнопкой
Говорит: Гайфуллин А.Р.

[На экране: сеть, локальный клиент, кеш.]

Основная кнопка собирает доступные результаты из сети и дополняет их локальной историей выбранного игрока из osu!stable и osu!lazer.

Используются recent, best, firsts и pinned. Доступность списков зависит от источника. Совпадающий результат не записывается повторно, разные попытки одной карты сохраняются отдельно.

Данные и расчеты кешируются. Карты анализирует rosu-pp-py, сервер работает на FastAPI, история хранится в SQLite. Для базового входа пароль и cookie не нужны.

Передаю слово Недугову - он расскажет о моделях и проверке качества.


СЛАЙД 06. Две задачи. Две проверки качества.
Говорит: Недугов Д.

[На экране: логистическая регрессия для pass и градиентный бустинг для accuracy.]

Здесь две отдельные задачи. Первая - оценить вероятность прохождения. Используется логистическая регрессия. Ее Brier score сравнивается с простым прогнозом по прошлой доле проходов игрока.

Вторая задача - предсказать accuracy полного прохождения. В показанном эксперименте V2 используется градиентный бустинг с 56 признаками. Качество сравнивается с Ridge и средним accuracy прошлых проходов. Эта версия подключалась для игры без модов, то есть NM.

Best отражают достижения, но не полную историю попыток. Поэтому ими нельзя заменять обычные проходы и провалы. Результат с No Fail также не считается обычным проходом без этого мода.


СЛАЙД 07. Ошибка accuracy снизилась примерно на 7%
Говорит: Недугов Д.

[На экране: MAE 4.35; сравнение 5.69, 4.67 и 4.35.]

На слайде результат личного эксперимента для одного игрока в NM. Проверены 403 более поздних прохода из 239 семейств карт.

Средняя абсолютная ошибка новой модели - 4.35 процентного пункта. У прежней Ridge - 4.67, у среднего прошлых проходов - 5.69. Относительно Ridge ошибка снизилась примерно на семь процентов.

Процентный пункт - разница между прогнозом и результатом. Если прогноз 90 процентов, а результат 94, ошибка равна четырем пунктам.

Обучение и выбор модели проводились на ранней истории, проверка - на более поздней. Для каждой игры использовалась только доступная до нее история. Это измерение на сохраненных данных одного игрока.

Теперь Темиров расскажет о тестировании и документах.


СЛАЙД 08. Тесты проверяют поведение, метрики - прогноз
Говорит: Темиров А.М.

[На экране: 149 тестов и таблица REQ-02 / REQ-06.]

В вынесенном на слайд прогоне прошли 149 тестов. Они проверяют импорт, API, модели и кеш.

Таблица показывает связь с требованиями. Для REQ-02 проверяем корректные .osu и .osz, а также отклонение поврежденного файла. Для REQ-06 - что модель подключается только при меньшей ошибке, чем у базового метода.

Есть три условия: модель лучше, хуже и ровно равна базовой оценке. Контрольные числа Brier заданы специально для проверки правила. Они не являются реальными метриками игрока.

Ответы API и результаты тестов сохранены. Качество самого прогноза измеряется отдельно, как на предыдущем слайде.

СЛАЙД 14. Как устроено приложение
Говорит: Гайфуллин А.Р.

[На экране: браузер, расчет, данные.]

В браузере пользователь выбирает профиль и карту, видит шкалы, график и рекомендации.

Сервер на Python и FastAPI получает запрос. rosu-pp-py рассчитывает нагрузку карты, scikit-learn используется для ML-моделей. История результатов, исходные поля и кеш анализа хранятся в SQLite.

Общий путь: профиль и карта, затем признаки и модель, затем персональный отчет.
