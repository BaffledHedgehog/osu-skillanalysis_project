## Как читать план в ProjectLibre

- Слева каждая строка - одна работа или веха. Код 1.1 означает первый блок работ и первую задачу в нем. Всего 6 блоков: требования, данные, модели, приложение, проверка, передача.
- Duration - число рабочих дней. Start и Finish - когда работа начинается и заканчивается. Нулевую длительность имеют вехи: момент, когда получен важный результат.
- Справа полоски показывают длительность на календаре, черные ромбы показывают вехи, стрелки показывают, какая работа должна закончиться до следующей.
- Красные работы находятся на критическом пути: их задержка сдвигает финальную дату, если не изменить план. Последняя веха и сдача - 7 ноября. Резерва после этой даты нет.
- Если последняя веха стоит на 11 ноября или в декабре, открыт старый файл. Закройте его без сохранения и снова откройте обновленный .pod.

RACI хранится внутри .pod в текстовых полях задач: Text1 = R, Text2 = A, Text3 = C, Text4 = I. Те же роли расписаны в заметках каждой задачи. Чтобы увидеть матрицу рядом с календарным планом, в таблице Ганта нажмите правой кнопкой на заголовке столбца и добавьте столбцы Text1, Text2, Text3, Text4. Коды WBS связывают задачи с отдельной таблицей RACI.

Основная роль исполнителя записана в Text5 и в заметках задач .pod, а также в таблицах календарного плана и WBS. В реестре у каждого требования есть ответственная роль. Соответствие ролей участникам находится в паспорте и на листе 'Роли' файла RACI: заказчик / руководитель - Ляхов Я.П.; данные и модели - Недугов Д.; разработка - Гайфуллин А.Р.; тесты и документы - Темиров А.М. Подготовка документов идет параллельно итоговой оценке моделей.

Заказчик проекта - Ляхов Я.П., автор идеи и руководитель команды. Он принимает результат приложения. Преподаватель проверяет проект по требованиям курса. В RACI приемка заказчиком и проверка на курсе показаны отдельно.

## Показ на защите

По лекции 7 ориентир финальной защиты - 20-25 минут: презентация, артефакты, MVP и вопросы. Покажите цепочку: проблема и цель -> ТЗ и REQ/AC -> WBS и ProjectLibre -> тест и доказательство -> решение по приемке. Точный тайминг задает преподаватель.

Каждый участник должен выступить или ответить на вопрос. Удобное распределение: Ляхов - проблема, цель и границы; Недугов - данные, модель и метрики; Гайфуллин - приложение и работы по разработке; Темиров - проверки, RACI и календарный план. Это порядок выступления, а не новая таблица ролей.

Короткий словарь: WBS - список работ по блокам; веха - контрольная точка без длительности; RACI - кто делает, отвечает, консультирует и получает информацию; baseline - простой расчет для сравнения с моделью; Brier score - ошибка прогноза вероятности прохождения; MAE - средняя ошибка прогноза точности. Для обеих ошибок меньше значит лучше.

Документы, таблицы и XML создаются повторно командой `python deliverables/build_course_pack.py`. Для запуска нужны `python-docx`, `xlsxwriter` и `reportlab`; для PDF используются шрифты Arial из Windows. Только Canvas можно пересоздать командой `python deliverables/build_mvp_canvas.py`. После изменения XML файл .pod нужно пересоздать через `ConvertProjectLibre.java` с Java 21 и библиотекой установленного ProjectLibre. Обычный импорт XML в ProjectLibre 1.9.8 не переносит поля Text1-Text4, поэтому конвертер заполняет их после импорта и проверяет готовый .pod.
