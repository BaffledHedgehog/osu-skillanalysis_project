# План проекта pulse!

Студенческий проект Университета Иннополис. Дата: 03.10.2026.

## Задача

Звезды osu! показывают общую сложность карты. Они не учитывают навыки конкретного игрока. Цель проекта - оценить шанс прохождения выбранной карты и показать, где возникают основные нагрузки.

Первый режим - osu!standard. Для других режимов понадобятся отдельные признаки и модели.

## Текущая версия

1. Игрок вставляет ссылку на профиль osu!. Приложение получает recent и best scores без входа в аккаунт.
2. Игрок выбирает карту и моды. Приложение рассчитывает параметры карты и нагрузку по участкам.
3. Приложение строит профиль по результатам и показывает прогноз прохождения и точности.
4. После новой игры игрок может добавить результат вручную или импортировать `.osr`.

Прототип работает локально. Сервер написан на FastAPI. Данные лежат в SQLite. Интерфейс сделан на HTML, CSS и JavaScript.

## Источники данных

| Источник | Данные | Ограничение |
| --- | --- | --- |
| [Hinamizawa Player API](https://mirror.hinamizawa.ai/docs/player) | Открытый профиль, до 100 recent и 100 best scores | Сторонний сервис. При повторах карт итог меньше 200. |
| [osu! API v2](https://osu.ppy.sh/docs/) | Профиль, результаты, пагинация | Нужен токен приложения. Для массового сбора данных API не рассчитан. |
| Файлы `.osu` и `.osz` | Объекты, тайминг, метаданные карты | Файл карты может быть удален или недоступен. |
| Файлы `.osr` и ручной ввод | Результаты игрока | Данные добавляет сам игрок. |

Приложение удаляет повторы карт. При пересечении recent и best оно оставляет recent попытку. Best scores нужны для оценки достигнутого уровня и PP. Для обучения шанса прохождения они не подходят: все они отобраны по успешности.

## Модель

Признаки карты: звезды, aim, speed, AR, OD и длина. Начальный прогноз опирается на похожие карты и недавние игры.

После накопления данных обучается логистическая регрессия для `P(pass)`. Условия: 40 попыток, 10 карт, 8 проходов и 8 неудач. Для проверки целые карты исключаются из обучения. Метрика - Brier score. Если модель хуже оценки по общей доле проходов, приложение оставляет начальный прогноз.

Ожидаемая точность пока считается отдельно по истории игрока. Ее интервал не является статистической гарантией.

## Проверка результата

1. Собрать добровольные попытки после выдачи прогноза.
2. Сравнить вероятность с фактическими проходами. Посчитать Brier score и калибровку.
3. Проверить новые карты отдельно от карт из обучения.
4. Сравнить подбор с простым выбором по звездам.

Тестовый набор в репозитории проверяет код. Он не подтверждает точность прогноза на реальных игроках.

## Похожие проекты

- [osu!Skills](https://www.osuskills.com/training) оценивает навыки и дает тренировочные карты.
- [osu!COACH](https://osu.jeff-dev.fr/) совмещает анализ навыков и подбор карт.
- [osu-skill-predictor](https://github.com/nayutalienx/osu-skill-predictor) предсказывает pass и accuracy с помощью ML.

Отличие, которое нужно проверить на пользователях: оценка риска по участкам карты и измерение результата конкретной тренировки. Одного прогноза pass недостаточно для нового проекта.
