# Общий датасет и модель pulse!

04.11.2026 владелец проекта сообщил о согласии всех 155 игроков из списка кандидатов. Для этого сбора используются публичные игровые результаты для обучения и проверки модели. Локальные файлы, реплеи и публикация исходных данных отдельно не согласованы.

## Где лежат данные

- `deliverables/dataset-candidates.csv`: список аккаунтов и отметка `owner_confirmed`.
- `.data/population/consents.json`: область согласия и ссылка на сообщение владельца. Индивидуальных подтверждений в проекте нет.
- `.data/population/raw/ID/`: полученные профиль, recent, best и firsts.
- `.data/population/population.db`: исходные результаты в `score_payloads`, карты и проверенные строки `plays`.
- `.data/population/players.json`: результат запроса каждого игрока и число записей по спискам.
- `.data/population/status.json`: ход сбора карт.
- `.data/population/quality.json`: итоги проверки модов, исходов и версий карт.
- `.data/population/training/`: признаки и схема разделения данных.
- `.data/population/model.json`, `report.json`: веса и оценка последнего эксперимента.
- `.data/population/runs/HASH/`: сохраненная версия входов, схемы, весов и отчета.

Папка `.data`, список участников и отметки согласий исключены из git. В репозитории находятся скрипты и сводные отчеты. Чтобы подготовить новый список кандидатов, запустите `python deliverables/collect_dataset_candidates.py`; действующие согласия задаются отдельно в локальном `consents.json`. Рабочая история пользователя не смешивается с общей базой. Из нее переиспользуется только кеш карт. Все сетевые запросы в этом сборе идут без cookie и токенов игроков.

## Повторить сбор и обучение

Из корня проекта:

```powershell
python -m app.population_data --phase scores
python -m app.population_data --phase charts --recent-only-players --context-limit 30
python -m app.population_data --phase normalize
python -m app.population_ml
python deliverables/build_population_report.py
```

Без `--force` уже полученные списки не скачиваются заново. Для новых результатов после игровых сессий:

```powershell
python -m app.population_data --phase all --force --recent-only-players --context-limit 30
python -m app.population_ml
python deliverables/build_population_report.py
```

Новые score_id добавляются, совпадающие обновляются. Предыдущие исходные результаты остаются в базе. Список игроков ограничен действующими согласиями в `consents.json`; одного присутствия в CSV недостаточно. Обновление списка приглашений не выдает согласие новым аккаунтам.

Для загрузки карт всех пригодных best/firsts можно отдельно запустить:

```powershell
python -m app.population_data --phase charts --context-limit 0
python -m app.population_data --phase normalize
```

Это большой сбор. Для первого эксперимента запрашиваются все пригодные recent-карты и до 30 карт best/firsts на игрока с пригодными recent. Выбор контекстных карт детерминирован по score_id, результат карты на него не влияет. Все исходные списки сохраняются целиком, независимо от этой выборки карт. Общие карты из кеша тоже доступны для признаков.

Сетевые ошибки повторяются с задержкой, 429 учитывает Retry-After. Одновременно загружается не более шести файлов карт, запуск запросов ограничен четырьмя в секунду. Карты берутся из кеша Hinamizawa с резервным запросом к osu!. Загружаются только .osu, без музыки и видео. Записи карты идут в SQLite небольшими пакетами; сетевые запросы не держат транзакцию базы.

## Что считается меткой

Для pass используется только явное булево `passed` обычной попытки recent. NF, неизвестный исход, чужой user_id, другие режимы и неподдерживаемые настройки модов не превращаются в метки pass. Для accuracy используются только успешные обычные попытки. Best и firsts могут описывать прежние навыки, но не заменяют обычные проходы и провалы.

Перед обучением `normalize` заново строит производную таблицу `plays` из исходных результатов. Он проверяет checksum карты, если источник его передал. Несовпадающая версия карты исключается; исходная запись остается. Таблица исходных результатов при этом не очищается.

## Как устроен эксперимент

Модели: логистическая регрессия для pass и Ridge для accuracy. На входе 63 признака: нагрузка карты и модов, описание прежних игр и разница между требованиями карты и показанными навыками. Ник, текущие pp и место в рейтинге не входят в признаки. PP используются для набора групп и балансировки обучения.

Целевые игроки и семейства песен делятся на train, validation и test до обучения. Для каждого примера профиль строится по строго более ранним играм на семействах train. Равные по времени и будущие результаты не используются. Результат целевой карты и ее семейства исключается из контекста. В профиле до 100 прежних обычных результатов и до 30 best/firsts; давность учитывается с полупериодом 60 дней.

В обучении диапазоны pp имеют равный суммарный вес, игроки внутри диапазона тоже равны по весу. При оценке игроки имеют равный вес независимо от числа попыток. Сохраняются Brier для pass, MAE для accuracy и ошибки по диапазонам pp.

Две базы сравнения: постоянное среднее по train и оценка по прежней истории игрока. Модель должна улучшить обе базы в validation и test. В каждой проверочной части нужны хотя бы 5 игроков и 30 примеров, а для pass еще хотя бы по 8 проходов и провалов. Применение ограничено модами с отдельной проверкой и диапазоном навыков, представленным в обеих проверочных частях. Веса без выполненной проверки остаются кандидатом.

Это проверка переноса между игроками и песнями на сохраненной истории. Качество будущих прогнозов измеряется отдельно. Пустой recent у участника означает отсутствие доступных обычных попыток, а не отсутствие навыков.

## Применение в приложении

Проверенная общая модель служит резервом, когда личной ML не хватает данных или проверки. Личная модель accuracy на обычных попытках сохраняет приоритет. Исходная история игрока и прогноз по известным попыткам той же карты продолжают использоваться.

По умолчанию приложение читает `.data/population/model.json`. Обучение при запросе прогноза не запускается. Другой файл можно указать через `PULSE_POPULATION_MODEL`. Статус и агрегированные метрики доступны в `GET /api/population/model`; исходные записи игроков этот маршрут не возвращает.

Отчеты для просмотра: `deliverables/Датасет и общая модель - pulse!.docx`, одноименный `.xlsx` и `population-summary.json`.
