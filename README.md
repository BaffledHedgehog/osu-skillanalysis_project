# pulse! - анализ карт osu!standard

Студенческий проект Университета Иннополис. Приложение сравнивает карту с результатами игрока и оценивает ее персональную сложность.

## Что работает

- Импорт карт по ссылке, ID, файлу `.osu` или архиву `.osz`.
- Расчет звезд, aim, speed и нагрузки по участкам с помощью `rosu-pp-py`.
- Импорт профиля по ссылке вида `https://osu.ppy.sh/users/12345678`. Вход в osu! не нужен.
- Загрузка до 100 recent и 100 best scores. Повторы карт убираются. В профиле видны точность, лучший PP и число результатов каждого типа.
- Прогноз прохождения и точности. Подбор карт из локального каталога.
- Ручной ввод результата и импорт собственного `.osr`.

## Запуск

Нужен Python 3.11 или новее.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Откройте `http://127.0.0.1:8000`. В поле игрока вставьте ссылку на профиль и нажмите "Загрузить". Приложение получит результаты и откроет первую карту. Новые игры после запуска не нужны.

Кнопка "Загрузить примеры" добавляет четыре карты. Можно добавить свою карту по ссылке или файлом.

## Откуда берутся результаты

По умолчанию приложение использует [открытый API Hinamizawa](https://mirror.hinamizawa.ai/docs/player). Он отдает публичные результаты без ключа. Ссылка на профиль передается этому сервису. Он возвращает не более 100 записей recent и 100 best. Если одна карта встречается несколько раз, уникальных карт будет меньше. Данные могут задерживаться или быть недоступны при сбое сервиса.

Официальный [osu! API](https://osu.ppy.sh/docs/) можно включить отдельно. Создайте `.env` по образцу `.env.example`, заполните `OSU_CLIENT_ID` и `OSU_CLIENT_SECRET` и перезапустите сервер. Тогда приложение сможет читать следующие страницы результатов, пока не соберет до 100 разных карт из каждого списка. Лимит чтения - 10 страниц на список. Это ключи приложения, а не пароль игрока.

Для публичных результатов авторизация игрока не нужна. Официальный osu! API требует токен приложения даже для чтения таких данных. Приложение не читает cookie браузера и токен игрового клиента.

## Как считается прогноз

До обучения ML приложение сравнивает карту с прошлыми результатами игрока. Числовой прогноз появляется после трех результатов.

Локальная логистическая модель обучается после 40 попыток на 10 картах, если есть хотя бы 8 проходов и 8 неудач. В обучение входят recent, ручные результаты и реплеи. Best scores не входят: это выборка удачных игр. Модель проверяется на картах, которых не было в обучении. Она используется, только если ее Brier score лучше простой оценки по доле проходов. Статус доступен по `/api/users/ИМЯ/model`.

Прогноз и интервал точности пока экспериментальные. Для проверки на реальных игроках нужны новые результаты после прогноза.

## Данные и тесты

Карты и результаты хранятся локально в `.data/`. Модель обучается на этих данных и хранится в памяти сервера. Ключи из `.env` не передаются в браузер.

```powershell
python -m pytest -q
```

Тесты проверяют импорт карт, профилей и реплеев, удаление повторов, обучение модели и работу API без OAuth ключей. План проекта находится в [PROJECT_PLAN.md](PROJECT_PLAN.md).
