# pulse! - анализ карт osu!standard

Студенческий проект Университета Иннополис. Приложение сравнивает карту с результатами игрока и оценивает ее персональную сложность.

## Что работает

- Импорт карт по ссылке, ID, файлу `.osu` или архиву `.osz`.
- Расчет звезд, aim, speed и нагрузки по участкам с помощью `rosu-pp-py`.
- Импорт профиля по ссылке вида `https://osu.ppy.sh/users/12345678`. Вход в osu! не нужен.
- Загрузка до 100 recent и 100 best scores. Повторы карт убираются. В профиле видны точность, лучший PP и число результатов каждого типа.
- Прогноз прохождения и точности. Подбор карт из локального каталога.
- Ручной ввод результата и импорт собственного `.osr`.

## Запуск

Нужен Python 3.11 или новее.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Откройте `http://127.0.0.1:8000`. В поле игрока вставьте ссылку на профиль и нажмите "Загрузить". Приложение получит результаты и откроет первую карту. Новые игры после запуска не нужны.

Кнопка "Загрузить примеры" добавляет четыре карты. Можно добавить свою карту по ссылке или файлом.

## Откуда берутся результаты

Кнопка "Из локального osu!" читает результаты osu!stable и osu!lazer. Поиск учитывает стандартные папки, запущенный клиент, `OSU_PATH` и перенос хранилища lazer через `storage.ini`. Можно указать папку вручную. Stable читает `scores.db` и карты из `Songs`. Lazer читает временную копию `client.realm` и находит карты и реплеи в хранилище `files` по SHA-256. Исходные файлы игры не меняются. Формат хранилища описан в [osu! wiki](https://osu.ppy.sh/wiki/en/Client/Release_stream/Lazer/File_storage).

Для lazer нужен .NET SDK 8 или новее: при первом импорте собирается небольшой модуль `tools/LazerReader` с библиотекой Realm из NuGet. Дальше используется готовая сборка. Если клиент меняет базу во время копирования, закройте его и повторите импорт.

Импорт lazer читает сохраненный Rank: F означает провал, D/C/B/A/S/SH/X/XH - проход. Неполная попытка с F сохраняется для обучения pass, но не для accuracy полной карты. В stable поле pass по одному scores.db по-прежнему неизвестно. Старые локальные записи уточняются при повторном импорте без дубликатов. Формат Rank подтверждается в [ScoreInfo](https://github.com/ppy/osu/blob/master/osu.Game/Scoring/ScoreInfo.cs) и [ScoreRank](https://github.com/ppy/osu/blob/master/osu.Game/Scoring/ScoreRank.cs).

No Fail импортируется и показывается отдельно. Полные результаты могут использоваться для accuracy с учетом NF как признака. В модель обычного pass они не входят. Ранг при NF не определяет, умер бы игрок без этого мода. Нестандартные настройки модов при массовом импорте пока пропускаются.

Кнопка "Посчитать HP для No Fail" запускает отдельный процесс с официальными пакетами osu! Game и osu!standard 2026.916.0. Он воспроизводит курсор и нажатия через ReplayPlayer, рассчитывает реальные игровые judgements, тики, дренаж и восстановление HP. Подходит для NF-реплеев stable и lazer. CL выбирает обработчик здоровья через правила самого движка. График не берется из пустой HP-строки заголовка: в lazer она [не заполняется](https://github.com/ppy/osu/blob/master/osu.Game/Scoring/Legacy/LegacyScoreEncoder.cs).

Для расчета нужен .NET SDK 10 и доступ к NuGet при первой сборке. Поддерживается системный `dotnet` или локальная установка `.data/tools/dotnet`. В окне можно выбрать NF-попытку из локального импорта или загрузить свой .osr; точная .osu должна быть в каталоге. Повторный импорт добавляет ссылки на сохраненные реплеи. Расчет берет только копии файлов, работает без окна игры, ограничен 3 минутами и выполняется по одному заданию. Результат кешируется по версии обработчика, хешу реплея и карте.

Момент возможного провала без NF фиксируется по событию Fail обработчика игры, а не просто по достижению нулевого HP между нотами. Проверяется совпадение воспроизведенной статистики с сохраненной. Если статистика отличается, результат помечается диагностическим. Для неполных записей и EZ с дополнительными жизнями конечный исход без NF пока не подтверждается. Время на графике - время карты, не реальное время с учетом DT/HT. Версия движка может отличаться от версии исходной игры: это расчет в указанных правилах, не гарантия полного совпадения со старым клиентом.

Исход NF-попытки в игровой истории не меняется, новая попытка без NF не создается. Загруженные отдельно .osr для анализа HP не используются для обучения accuracy. Расчет доступен только локально, через публичный relay он заблокирован. Сопоставление движений и нажатий с отдельными навыками пока остается следующим этапом.

Повторный импорт дополняет историю без дубликатов. Неизменившиеся локальные базы и анализ игрока берутся из кеша; новый результат обновляет расчеты. Онлайн-импорт кешируется на 5 минут, кнопка обновления запускает повторный запрос.

Кнопка cookie принимает JSON из Cookie Editor, Netscape `cookies.txt` или строку `Cookie`. Сессия необязательна и хранится только в памяти локального сервера до 8 часов. Она отправляется только на `https://osu.ppy.sh`, не в зеркала. Можно запросить дополнительные страницы истории, но доступ зависит от ограничений сайта. Автоматического чтения cookie браузера и токенов клиента нет.

Для JSON принимаются домены `osu.ppy.sh` и родительский `ppy.sh`, сроки действия в секундах, миллисекундах, ISO и HTTP-date, а также сессионные cookie. Экспорт должен включать HttpOnly `osu_session`: одного XSRF-TOKEN недостаточно. Сообщение об ошибке остается внутри окна импорта, всплывающее уведомление тоже отображается поверх окна. Принятый формат не гарантирует действующую сессию: сайт проверит ее при загрузке истории. Ошибки 401 и 403 объясняются отдельно.

Кнопка "Подключить OAuth / официальный API" открывает инструкцию и поля Client ID / Client Secret. Ключи проверяются запросом токена до сохранения сессии и остаются только в памяти на 8 часов. Официальный API используется вместо cookie. Отключение удаляет ключи этой сессии; настройки `.env` не меняются. Через публичное HTTP-демо ввод ключей отключен, инструкция доступна. Используйте локальную версию для подключения.

По умолчанию приложение использует [открытый API Hinamizawa](https://mirror.hinamizawa.ai/docs/player). Он отдает публичные результаты без ключа. Ссылка на профиль передается этому сервису. Он возвращает не более 100 записей recent и 100 best. Если одна карта встречается несколько раз, уникальных карт будет меньше. Данные могут задерживаться или быть недоступны при сбое сервиса.

Официальный [osu! API](https://osu.ppy.sh/docs/) также можно настроить постоянно через `.env`: заполните `OSU_CLIENT_ID` и `OSU_CLIENT_SECRET` по образцу `.env.example` и перезапустите сервер. Ключи создаются в [настройках аккаунта](https://osu.ppy.sh/home/account/edit#oauth), раздел OAuth Applications. Для используемого Client Credentials поле Callback URL можно оставить пустым. Эти шаги описаны в [документации аутентификации osu!](https://osu.ppy.sh/docs/#authentication). Лимит чтения - 10 страниц на список. Это ключи приложения, а не пароль игрока; доступа ко всему архиву игр они не дают.

Для публичных результатов авторизация игрока не нужна. Официальный osu! API требует токен приложения даже для чтения таких данных. Приложение не читает cookie браузера и токен игрового клиента.

## Как считается прогноз

Модель получает скорость стримов и бурстов, долю слайдеров, изменение ритма, AR, моды и сочетания этих признаков с Hidden. Добавлены квадратичные признаки AR и скорости серий, чтобы зависимость не сводилась к прямой линии. Коэффициенты обучаются на попытках игрока. Скорость стримов считается по последовательностям минимум из 7 нот, в BPM четвертями с учетом DT/HT. BPM песни сам по себе не запрещает карту.

Отдельные признаки описывают короткие пики нагрузки: максимальный aim/speed, суммарный пик, отношение пика к средней нагрузке и пик в последних 10% участков карты. Они извлекаются из исходных strain-секций, а не из общего среднего карты. Это позволяет обучению учитывать короткий сложный финал, но само по себе не гарантирует точный прогноз.

Если есть известные исходы этой версии карты с теми же модами, прогноз дополнительно уточняется статистической моделью: исходная оценка служит априорной, сохраненные проходы и провалы обновляют ее как Beta-постериор. Чем больше попыток, тем сильнее их влияние. Best и NF в этот подсчет не входят. Жесткого ограничения вероятности здесь нет. Такой результат подписан как прогноз с учетом истории карты; его качество еще нужно оценить на будущих попытках. Количество сохраненных результатов не равно полному счетчику запусков карты в клиенте.

Давность учитывается и при ML-обучении, и в сравнении карт, и в истории конкретной карты. Базовый вес уменьшается вдвое за 60 дней: результат полугодовой давности получает около 12.5% свежего веса до поправки на объем игр. Суммарный вес одной календарной недели ограничен 30 условными попытками, чтобы большая старая серия не подавляла небольшую свежую. Даты без часового пояса считаются UTC, записи без даты получают пониженный вес. Старые результаты не удаляются. Нормировка весов при обучении использует эффективный размер выборки; базовая оценка и метрики проверки взвешиваются по той же давности. Кеш моделей обновляется при новых данных и смене суток.

Прогресс показывается по повторно сыгранным версиям карт с теми же модами: последние 30 дней сравниваются с днями 31-180. Считаются медианные изменения accuracy на полных пройденных попытках и доли проходов на попытках с известным исходом. Для каждого показателя нужны хотя бы 5 совпавших карт. Это наблюдение на повторных картах, не общий рейтинг навыка и не доказательство причин прогресса. NF и best в сравнение не входят. Качество прогноза на следующих играх остается отдельной проверкой.

Ручных пределов и принудительного ограничения до 1% нет. Низкая вероятность должна следовать из результатов обучения, включая неудачные попытки. Best и локальные записи с неизвестным pass не дают такой разметки. Если скорость, AR или чтение с HD выходят за наблюдавшийся диапазон, приложение показывает "шанс неизвестен" и причину. Это проверка наличия данных, а не утверждение о физическом пределе игрока. Нижнего порога 2% тоже нет.

Для сложной карты или неизвестного диапазона появляется подбор более простых карт с похожим соотношением aim/speed, долей слайдеров, ритмом и AR. Кандидаты берутся из добавленного каталога, с теми же модами, прогнозом от 95% accuracy и pass от 60%. Карты с неизвестным шансом не выдаются за подходящие. Если кандидатов нет, приложение сообщает об этом. Это первый вариант подбора, до полной модели 16 навыков.

До обучения ML приложение сравнивает карту с прошлыми результатами игрока. Числовой прогноз появляется после трех результатов.

Локальная логистическая модель обучается после 40 попыток на 10 картах, если есть хотя бы 8 проходов и 8 неудач. В обучение входят recent, ручные результаты и реплеи. Best scores не входят: это выборка удачных игр. Модель проверяется на картах, которых не было в обучении. Она используется, только если ее Brier score лучше простой оценки по доле проходов. Статус доступен по `/api/users/ИМЯ/model`.

Для accuracy подключена отдельная линейная ML-модель Ridge. Нужны 40 подходящих результатов на 10 картах. Сначала используются обычные попытки, затем полные локальные результаты; если их мало, модель может обучиться отдельно на best. В таком случае интерфейс показывает "ML: точность по best-результатам": это оценка удачной игры, смещенная к лучшим результатам игрока.

Проверка исключает целые карты из обучения: 25 процентов карт оставляются для оценки. Средняя ошибка MAE сравнивается с простым средним accuracy. Модель используется только при меньшей ошибке. Карты вне диапазона звезд обучающей истории получают предварительный расчет. Интервал отражает ошибки на проверочных картах и не является статистической гарантией. Качество на будущих играх еще нужно измерить.

Модели подхватываются автоматически при расчете. Кнопка "Обучить и проверить ML" запускает обучение повторно и обновляет отчет. То же самое из терминала:

```powershell
python -m app.ml baffledhedgehog
```

Вместо `baffledhedgehog` укажите ник загруженного игрока. API обучения: `POST /api/users/ИМЯ/model/train`.

Ранее на профиле baffledhedgehog проверена версия с 6 признаками: 97 best-результатов, 25 карт вне обучения; MAE accuracy 1.88 п.п. против 2.64 п.п. у среднего. Это исторический результат, не метрика текущей версии. Сейчас добавлены CS, признаки модов и взаимодействие HD с AR; актуальные метрики показывает обучение в приложении. План расширения навыков: [SKILLSETS.md](SKILLSETS.md).

## CNN и отражения карт

Установить дополнительную зависимость:

```powershell
python -m pip install -r requirements-cnn.txt
```

В приложении нажми "CNN: паттерны карты и обучение". Окно показывает ход обучения, сравнение вариантов и решение о подключении каждого выхода. Модель использует последовательность нот, геометрию слайдеров и историю игрока. Обучение сравнивает оригинал, X, Y, XY, все четыре варианта и контроль без последовательности нот. Все отражения сохраняют целевой результат. Они создаются после разделения данных и не добавляются в историю как реальные игры.

Запуск из терминала (замени USER своим ником):

```powershell
python -m app.sequence_train USER --output .data/cnn-experiment --steps 400 --pretrain-steps 200
python -m app.sequence_train USER --output .data/cnn-experiment --audit
```

Для автоматического подключения используй кнопку: она выбирает папку модели именно этого игрока и базы. Второй вызов проверяет сохраненные веса на точном снимке данных без повторного обучения. Снимок содержит карты и попытки игрока, поэтому папка .data исключена из git. Веса записываются числовым NPZ без pickle.

Для проверки целые семейства песен делятся на обучение, выбор модели и итоговый тест. Проверка использует оригинальные карты. CNN accuracy подключается при улучшении MAE и подтверждении разницы повторными выборками семейств. CNN pass дополнительно требует достаточно проходов и провалов. Если выход не прошел проверку или карта вне обучающего диапазона, сохраняется прежний расчет.

В эксперименте 24.10.2026 на 1680 попытках CNN снизила MAE accuracy с 5.91 до 5.49 п.п. при одинаковой проверке с контрольной моделью. Лучшим оказался вариант без отражений. CNN pass проверку не прошла: в итоговой части всего 5 провалов. По объему проверки accuracy сейчас подходят NM и CL. Для HD и других редких сочетаний данных недостаточно. Качество на будущих играх еще предстоит измерить.

В этом же окне есть отдельная модель ошибок по участкам. Кнопка "Подготовить реплеи и обучить" разбирает локальные реплеи stable и lazer официальным движком osu!, сверяет статистику и привязывает события к нотам. Она сравнивает CNN без отражений и со всеми четырьмя вариантами с логистической регрессией по признакам ноты. Неполные реплеи и несовпавшие результаты не размечаются как полная карта.

Локальные выходы: промах или срыв комбо; попадание ниже 300 на круге или голове слайдера. Итоговая оценка слайдера не выдается за ошибку тайминга. Эти события не определяют причину ошибки. Карты выбираются без отбора по accuracy или промахам; набор состоит из законченных локальных реплеев, а не всех попыток игрока.

Перед обработкой автоматически проверяется отключение звука. Задачу можно остановить кнопкой, готовый кеш сохраняется. Для команды ниже нужны .NET SDK 10 и PyTorch:

```powershell
python -m app.sequence_local USER --output .data/local-experiment --collect 120 --steps 400 --pretrain-steps 200
python -m app.sequence_local USER --output .data/local-experiment --audit
```

При успешной проверке окно карты показывает ожидаемую долю нот с ошибкой по участкам. Если улучшение не подтверждено, числовой прогноз по участкам не показывается. Вероятность провала участка из доли ошибочных нот не вычисляется.

В эксперименте 24.10.2026 сверку прошли 108 из 120 реплеев. Локальная CNN улучшила общие метрики, но отдельные проверки NM и CL не подтвердили надежную разницу. Поэтому локальные выходы сохранены для экспериментов и не включены в прогноз. Обе проверки и причины решения видны в отчете. Профиль при использовании CNN строится по тем же обучающим семействам песен, что и при проверке модели.

Кнопка "Проверить на новых попытках" использует только игры после даты сохранения модели. Для каждой игры профиль восстанавливается по более ранней истории, ее собственный результат не входит в признаки. Веса и решение о подключении не меняются. Без новых игр окно сообщает об отсутствии данных. Проверка из терминала:

```powershell
python -m app.sequence_forward USER --run .data/cnn-experiment
```

## Данные и тесты

Удаленный доступ через RU-relay и расчеты на ПК: [RELAY.md](RELAY.md). Веб-версия использует отдельную базу и блокирует доступ к локальным файлам и cookie.

Карты и результаты хранятся локально в `.data/`. Обученные модели сохраняются в `.data/models/` как JSON с коэффициентами и метриками и загружаются после перезапуска. Новые результаты меняют выборку и запускают повторную проверку модели. Ключи из `.env` не передаются в браузер.

Для локального приложения остается SQLite: добавлены индексы, загрузка истории одним запросом и кеширование по версии данных. Для сервиса с несколькими процессами следующий шаг - PostgreSQL и общий кеш. Переход на NoSQL сам по себе не решает нагрузку от скачивания карт и расчета признаков.

```powershell
python -m pytest -q
```

Тесты проверяют импорт карт, профилей и реплеев, удаление повторов, обучение модели и работу API без OAuth ключей. План проекта находится в [PROJECT_PLAN.md](PROJECT_PLAN.md).
