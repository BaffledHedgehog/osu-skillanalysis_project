# pulse! — персональный анализ карт osu!

Локальный веб-прототип для **osu!standard**. Добавьте карту по ID/ссылке или загрузите `.osu`/`.osz`; приложение покажет звёзды и нагрузку по участкам. После добавления результатов оно начнёт оценивать вероятность прохождения и ожидаемую точность для выбранной карты и модов, а также подбирать карты из локального каталога.

## Запуск

Требуется Python 3.11+.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Откройте [http://127.0.0.1:8000](http://127.0.0.1:8000). Кнопка «Попробовать примеры» добавит четыре реальные карты разных уровней сложности, чтобы можно было проверить подбор. Также можно вставить ссылку вида `https://osu.ppy.sh/beatmapsets/123#osu/456` или загрузить локальную `.osu`/`.osz`.

Чтобы получить персональный прогноз, укажите ник и добавьте хотя бы три результата через кнопку «Добавить результат» у карты. Результат можно ввести вручную или импортировать собственный `.osr` из osu!stable. Для реплея нужно предварительно добавить точную версию карты; приложение сверяет хеш. Отметку «Карта пройдена» выставьте перед импортом. Для полноценного подбора добавьте несколько карт в каталог. Без истории интерфейс показывает сложность и нагрузку карты, но не числовой шанс прохождения.

## Необязательный импорт из osu! API

Зарегистрируйте OAuth-приложение в [настройках osu!](https://osu.ppy.sh/home/account/edit#oauth). Создайте `.env` по образцу `.env.example` и заполните `OSU_CLIENT_ID` и `OSU_CLIENT_SECRET`, затем перезапустите сервер. Импорт по имени игрока загрузит до 30 лучших и 30 недавних результатов, включая неудачные попытки, и не более 40 новых файлов карт за один запрос. Повторный импорт не создаёт дубликаты результатов.

Ключи остаются на сервере и не передаются в браузер. Приложение запускается и без ключей; в таком случае результаты вводятся вручную. Данные и файлы карт хранятся в `.data/osu_skill.db` на вашем компьютере.

## Как устроен прогноз

- [rosu-pp](https://github.com/MaxOhn/rosu-pp) рассчитывает звёзды, aim/speed и нагрузку с учётом модов.
- Первые прогнозы сравнивают карту с недавними играми того же пользователя и сглаженным ориентиром по сложности.
- Начиная с 40 попыток на 10 разных картах, при наличии хотя бы восьми успехов и восьми неудач, приложение обучает персональную логистическую модель. Целые карты откладываются для проверки; ML используется лишь если её Brier score лучше прогноза по общей доле успехов. Веса и метрики сохраняются локально в `.data/models/` как JSON. При новых попытках модель переобучается автоматически.
- Статус обучения и метрики доступны по `/api/users/ИМЯ/model`. Ручной запуск: `python -m app.ml ИМЯ`. Это модель **вероятности прохождения**; ожидаемая точность пока рассчитывается отдельно простым методом.
- Вероятности **экспериментальные и пока не откалиброваны** на независимом наборе. Интервал ожидаемой точности — ориентировочный, а не статистическая гарантия. Особенно осторожно трактуйте прогноз по одним top plays: они смещены к успешным играм.
- Подбор выбирает карты из добавленного пользователем каталога. Он не индексирует всю библиотеку osu!.

В текущей локальной базе нет настоящих попыток игрока, поэтому модель для реального профиля пока не обучена. Добавьте свои результаты или импортируйте их через osu! API. Одни лучшие результаты плохо подходят для обучения прохождений: нужны и неудачи. Публичные выгрузки [data.ppy.sh](https://data.ppy.sh/) в приложение не включены: их [условия](https://data.ppy.sh/LICENCE.txt) не дают автоматического разрешения на использование в публичном сервисе.

## Проверка

```powershell
python -m pytest -q
```

Тесты проверяют разбор `.osu`, влияние DT на параметры карты, импорт `.osr`, накопление результатов, обновление прогноза после неудачных игр, подбор и обучение ML на тестовом наборе с отложенными картами. Тестовый набор с искусственными исходами проверяет только работу контура обучения; он не подтверждает качество на реальных игроках.

## Что дальше

1. Привязка событий из импортированных `.osr` к конкретным паттернам, а не только к итоговому счёту.
2. Сбор добровольных будущих попыток и оценка качества на играх, которые модель ещё не видела; калибровка вероятностей.
3. Режим «тренировочный эксперимент»: предложить участок/набор карт, зафиксировать исходный уровень, затем проверить, улучшилась ли игра именно на этом паттерне.

Именно третий пункт выглядит наиболее интересным отличием от обычных рекомендателей. Анализ ошибок и тренировки как отдельные функции уже существуют; полезность будет определяться тем, насколько точно приложение измеряет **эффект тренировки для конкретного игрока**.
