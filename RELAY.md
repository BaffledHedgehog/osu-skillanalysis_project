# Веб-доступ через relay

Схема: браузер -> nginx на RU-сервере -> обратный SSH-туннель -> FastAPI на ПК.

На relay нет моделей и игровой базы. Он пересылает запросы. Модели, SQLite и расчеты остаются на ПК. Когда ПК выключен или туннель не работает, сайт отвечает 502. Туннель переподключается после обрыва связи.

## Запуск на ПК

После первичной настройки:

```powershell
python tools/relay/manage.py serve
```

Команда поднимает отдельный сервер на `127.0.0.1:8001` и SSH-туннель. Обычное локальное приложение остается на порту 8000. Остановка - Ctrl+C. После перезагрузки ПК команду нужно запустить снова.

Адрес сайта хранится в `.data/relay/config.json`: поле `host`, порт 8088. Это HTTP для демонстрации. Для постоянного доступа добавляем домен и HTTPS. Порт 443 и существующие сервисы relay не меняются.

## Первичная настройка другого сервера

Нужны Docker на сервере и OpenSSH на ПК. Дополнительная Python-зависимость нужна только для настройки:

```powershell
python -m pip install -r requirements-relay.txt
python tools/relay/manage.py bootstrap --host SERVER_IP --credentials-file C:\private\serverdata.txt
```

Внешний файл должен содержать строку `ssh root@SERVER_IP` и следующую строку с паролем после двоеточия. Содержимое файла и пароль не выводятся. Пароль используется при настройке и не сохраняется в проект.

Создаются только ресурсы pulse: контейнер `pulse-relay`, папка `/opt/pulse-relay`, пользователь `pulse-tunnel` и его SSH-ключ. Рабочий туннель подключается этим пользователем. Ключ ограничен обратным портом `127.0.0.1:18080`, без интерактивной оболочки. Ключ сервера фиксируется в `known_hosts`; при его смене соединение отклоняется.

Локальные настройки, ключ и отдельная веб-база находятся в `.data/relay`, которая исключена из Git. `.gitignore` также исключает `serverdata.txt`, `.private`, `.env` и файлы ключей. Не копируйте секреты в другие файлы проекта.

## Ограничения веб-версии

- Использует отдельную SQLite-базу `.data/relay/public.db`. Личная локальная история туда не копируется.
- `PULSE_PUBLIC_MODE=1` блокирует локальные файлы и cookie на уровне приложения, даже если туннель подключился с loopback-адреса. Nginx дополнительно блокирует эти маршруты.
- Локальный импорт из клиента игры доступен в локальной версии. Браузер посетителя не дает серверу доступ к его папке osu!.
- Веб-демо общее, без личных кабинетов. Добавленные результаты по одному нику доступны другим посетителям. Перед постоянным размещением нужны учетные записи и разделение данных.
- Загрузка файла ограничена 25 МБ. Nginx ограничивает частоту запросов и число соединений с одного IP. Приложение ограничивает число одновременных запросов. Это базовые ограничения для небольшого демо, не защита от большой нагрузки.
- Веб-приложение запускается с `--no-proxy-headers`, чтобы внешний заголовок не менял определение локального клиента.
- Cookie osu! через HTTP не принимаются. Ручные локальные сессии остаются в локальном приложении.
- OAuth-ключи через публичный HTTP тоже не принимаются. В окне подключения доступна инструкция; ввод работает в локальном приложении. Владелец сервера может настроить официальный API через `.env` на ПК.

Логи ПК: `.data/relay/client.log`, `.data/relay/client-error.log`. Лог nginx: `docker logs pulse-relay`. Контейнер запускается без привилегий, с файловой системой только для чтения и лимитом памяти 64 МБ. Доступ к журналу relay требует административного SSH; ключ туннеля команд не выполняет.

Справка: [обратные туннели OpenSSH](https://man.openbsd.org/ssh), [настройки proxy nginx](https://nginx.org/en/docs/http/ngx_http_proxy_module.html).
