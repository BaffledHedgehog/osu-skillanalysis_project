## Конфигурация и журналы

`DATABASE_PATH` задает путь SQLite, по умолчанию `.data/osu_skill.db`. `PULSE_PUBLIC_MODE=1` блокирует локальные функции для публичного стенда. `.env.example` содержит имена настроек. Секреты остаются в `.env` или памяти сеанса, не в git. Измененные переменные окружения читаются при новом запуске процесса.

Основные логи идут в stdout/stderr uvicorn. Стенд защиты пишет в `.data/defense-prep-2026-11-07/server.log` и `server-error.log`. Личные accuracy-модели лежат в `models` рядом с соответствующей базой; модель связана с базой, игроком и модами. Копирование JSON в случайную папку не подключит ее.

## Типовые проблемы

- Порт занят: проверить `Get-NetTCPConnection -LocalPort 8000 -State Listen`, выбрать свободный порт. Не завершать чужой процесс наугад.
- Нет публичной истории: проверить доступность источника; использовать уже сохраненную историю или импорт собственной локальной базы. Не считать недоступный источник полным отсутствием игр.
- Нет личной модели в новой копии: веса и данные не публикуются. Базовый сценарий работает; обучение и проверка описаны в `ACCURACY.md`.
- Модель отклонена: посмотреть метрики. Это штатный результат проверки, прежний расчет остается доступен.
- Lazer не импортируется: проверить .NET SDK и путь клиента; при изменении базы во время чтения закрыть клиент и повторить. Импорт читает временную копию Realm.
- Нативный разбор реплеев: на защите не запускать. Предыдущая проверка отключения аудио завершалась таймаутом; нужен отдельный разбор.

## Резервная копия и восстановление

Остановить свой процесс приложения. Скопировать базу, связанные `-wal`/`-shm`, если они остались, и каталог `models` в отдельную закрытую папку. Не выгружать туда cookie или .env без отдельной необходимости. Для работающей базы использовать SQLite backup API, а не копирование одного .db. Проверить целостность копии через `PRAGMA integrity_check` до замены рабочей базы. Восстановление: сохранить текущую версию отдельно, вернуть проверенную копию, запустить тот же код и проверить health и один анализ.

07.11 на отдельной контрольной базе проверен этот путь: backup API при запущенном сервере, integrity_check=ok, новый запуск восстановленной базы, совпадение числа результатов и полного отчета навыков. Основная база игрока не затрагивалась. Это не проверка переноса всех персональных весов и секретов. Протокол: `.data/defense-prep-2026-11-07/clean-install/result.json`, скрипт `tools/verify_handover.py`. Скрипт создает свежую папку и намеренно не перезаписывает прошлые доказательства; для повторного прогона нужно выбрать новую папку в настройке FOLDER.
